# Designing Good Functions

A well-designed function does *one thing* well.  The key principles are:

- **Single responsibility** — each function has one clear job
- **Descriptive name** — the name tells you exactly what it does
- **Docstring** — documents parameters and return value
- **Parameters for input** — data goes in through parameters, not `input()` inside the function
- **`return` for output** — data comes out through `return`, not `print()` inside the function (unless printing *is* the function's job)

## Refactoring a Poorly Designed Function

Study this function — it has too many responsibilities:

~~~python
# BAD — mixes input, logic, and output in one function
def process():
    name  = input("Name: ")
    score = float(input("Score: "))
    grade = "Pass" if score >= 60 else "Fail"
    print(f"{name}: {grade}")
~~~

The problem: you cannot reuse the grading logic without also triggering the input prompt and the print.  You cannot test the grade calculation independently.

Now compare the refactored version:

~~~python
# GOOD — each function has one job
def get_input(prompt):
    """Prompt the user and return their input as a string."""
    return input(prompt)

def calculate_grade(score):
    """Return Pass or Fail for a numeric score."""
    return "Pass" if score >= 60 else "Fail"

def display_result(name, grade):
    """Print a formatted result line."""
    print(f"{name}: {grade}")

# Main program — reads like plain English
name  = get_input("Name: ")
score = float(get_input("Score: "))
grade = calculate_grade(score)
display_result(name, grade)
~~~

Create a new Python file, enter the refactored version, and run it.
