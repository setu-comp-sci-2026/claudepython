# The LEGB Rule

When Python sees a name it searches for it in a fixed order — **L E G B**:

| Letter | Scope | Example |
|--------|-------|---------|
| **L** | Local — inside the current function | `x` defined in `my_func` |
| **E** | Enclosing — an outer function wrapping this one | Nested functions |
| **G** | Global — module level (top of the file) | `PI = 3.14159` |
| **B** | Built-in — Python's own built-ins | `len`, `print`, `range` |

Python stops at the first scope where the name is found.

## L — Local wins

Create a new Python file:

~~~python
x = "global"

def show():
    x = "local"      # shadows the global
    print(x)         # finds local first

show()      # local
print(x)    # global  — the global x is unchanged
~~~

The local `x` *shadows* the global — inside `show()`, the local version is found first and the global is never reached.

## E — Enclosing scope

~~~python
x = "global"

def outer():
    x = "enclosing"
    def inner():
        print(x)        # E found before G
    inner()

outer()     # enclosing
print(x)    # global
~~~

`inner()` finds `x` in the enclosing `outer()` scope before ever reaching the global.

Uncomment a local `x = "local"` inside `inner()` and run again — now L wins.

## B — Built-ins

You have been using built-ins all along without thinking about it:

~~~python
numbers = [5, 2, 8, 1, 9]
print(len(numbers))   # len is a built-in
print(max(numbers))   # max is a built-in
print(min(numbers))   # min is a built-in
~~~

Built-ins are always available because they live in the B layer — the last place Python looks.

> **Warning:** avoid naming your own variables `len`, `list`, `max`, `min`, `print` etc. — you would shadow the built-in and lose access to it.

~~~python
len = 10        # shadows the built-in
print(len([1, 2, 3]))   # TypeError: 'int' object is not callable
~~~
